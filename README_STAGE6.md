## 关键概念

### 评估指标

#### 1. Perplexity (困惑度)

**定义**：模型对测试数据的困惑程度，越低越好。

**公式**：
```
perplexity = exp(average_loss)
```

**含义**：
- 困惑度 = 10：模型平均在 10 个词中选择
- 困惑度 = 100：模型平均在 100 个词中选择
- 越低说明模型越确定

**适用场景**：
- 语言建模任务
- 对比不同模型
- 监控训练进度

#### 2. BLEU Score

**定义**：对比生成文本和参考文本的 n-gram 重叠度。

**范围**：0-100，越高越好

**适用场景**：
- 翻译任务
- 摘要任务
- 有标准答案的任务

#### 3. ROUGE Score

**定义**：对比生成文本和参考文本的召回率。

**类型**：
- ROUGE-1：单词重叠
- ROUGE-2：双词重叠
- ROUGE-L：最长公共子序列

**适用场景**：
- 摘要任务
- 问答任务

#### 4. 人工评估

**维度**：
- **相关性**：回答是否切题
- **准确性**：信息是否正确
- **流畅性**：语言是否自然
- **完整性**：回答是否完整
- **创造性**：是否有新见解

**评分标准**：
- 1 分：很差
- 2 分：较差
- 3 分：一般
- 4 分：较好
- 5 分：很好

### 评估方法

#### 自动评估

**优势**：
- 快速、可重复
- 客观、一致
- 适合大规模测试

**劣势**：
- 可能不符合人类判断
- 难以评估创造性
- 需要参考答案

#### 人工评估

**优势**：
- 更符合实际需求
- 可以评估主观质量
- 发现自动评估遗漏的问题

**劣势**：
- 耗时、成本高
- 主观性强
- 难以大规模进行

#### 混合评估（推荐）

1. 自动评估筛选（快速过滤明显问题）
2. 人工评估验证（深入评估质量）
3. A/B 测试（实际用户反馈）

### 评估流程

```
准备测试集
  ↓
运行模型推理
  ↓
计算自动指标（Perplexity, BLEU, ROUGE）
  ↓
人工评估样本（相关性、准确性、流畅性）
  ↓
对比基础模型 vs 微调模型
  ↓
分析问题和改进方向
```

## 常见问题

### Q: 困惑度降低了，但回复质量没提升？

**可能原因**：
- 过拟合：模型记住了训练数据
- 数据质量差：训练数据本身有问题
- 评估不全面：只看困惑度不够

**解决方案**：
- 增加训练数据多样性
- 进行人工评估
- 使用更多评估指标

### Q: 微调后模型变"笨"了？

**可能原因**：
- 灾难性遗忘：微调破坏了原有知识
- 数据偏差：训练数据太窄
- 过度微调：训练轮数太多

**解决方案**：
- 减少训练轮数
- 增加数据多样性
- 降低学习率
- 使用更小的 LoRA rank

### Q: 如何判断微调是否成功？

**成功标准**：
1. 困惑度降低（至少 10-20%）
2. 目标任务表现提升
3. 原有能力保持
4. 人工评估满意

### Q: 评估需要多少测试样本？

**推荐**：
- 自动评估：100-500 条
- 人工评估：20-50 条
- A/B 测试：10-20 条
